The schematic and the firmware used to disagree

Earlier in this project, wattplot.yaml was compiled from an older C3-era pinout, while the schematic had moved on. v3 brings the firmware into line with the schematic. v3.1 removes the limit switches entirely and uses motor-current-spike detection via IPROPI for endstops. If your board is wired to rev B, the current firmware is correct.

Why "compat" entries remain

Components that the schematic removed but the firmware keeps.

The state machine in wattplot.yaml still references id(hb_en_sw), id(solenoid_in2_out), and id(status_led) in scripts and automation. v3 keeps these IDs in the firmware but reassigned to schematic "free" pins. Their actions have no physical effect (the board doesn't wire them), but the script.execute calls keep working without rewriting the control law.

A future v4 could remove them entirely and rewrite the state machine to drive the H-bridge purely via IN1/IN2 (no EN) and the solenoid via a single IN1 (no IN2). Until then, the "compat" entries are inert placeholders.

See schematic.html for the full system diagram, wiring.html for cable runs, or the wattplot.yaml source on GitHub.
